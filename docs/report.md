# Краткий отчёт

Подготовлены аналитика, спецификация с 8 историями, диаграммы, API, backlog. Java реализует заявку, категории, конечный автомат, фильтрацию и транзакционную историю через JDBC. Kotlin реализует используемую API статистику; подготовлены модульные, PostgreSQL-интеграционные и сквозные проверки, Docker, CI/CD и эксплуатационные сценарии. План трудозатрат — 72 академических часа в backlog; фактическое время студента необходимо вести самостоятельно, план не является фактическим табелем.

## Взаимодействие языков и два решения Kotlin

Java ReportController вызывает Kotlin ReportService, который зависит от Java ReportSource. Реализация ReportSource — Java TicketStore, выдающий одну выборку PostgreSQL в [from,to). Kotlin обрабатывает Java record Ticket и enum; цикл компиляции исходников обслуживает Kotlin Gradle plugin.

1. Nullable `averageResolutionSeconds: Double?` отражает отсутствие завершённых заявок. `closedAt()?.let`, `mapNotNull` и `takeIf` исключают unsafe `!!`, отсутствующие даты и NaN пустого среднего. В JSON отсутствие среднего представлено null, а не 0.
2. `data class Summary` задаёт неизменяемую модель результата. `filter`, `mapNotNull`, `count`, `associateWith`, `average` работают с одной полученной коллекцией; enum entries гарантируют все группы, включая нулевые. Clock читается один раз на отчёт, поэтому счётчики согласованы на границе срока.

Статус и история изменяются в одной @Transactional Java-службе. SELECT FOR UPDATE запрещает конкурентным изменениям обходить проверку терминального состояния. Миграции накладывают FK, допустимые enum и согласованность closedAt. Время приложения внедряется через Clock.

Найденный граничный дефект и регрессия — defects.md. Фактически выполненные проверки, покрытие и ограничения — evidence.md; успешный CI/CD не заменяется подготовкой YAML. Ограничения: нет авторизации и внешних каналов, статистика по текущим статусам и учебному объёму; для крупной БД нужна агрегация SQL/лимиты периода.
